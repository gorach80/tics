¿Por qué medir la Disponibilidad?

El primer indicador de la metodología OEE

En las plantas de producción, medir cuánto tiempo trabaja realmente una máquina frente al tiempo que se planeó que trabajara es vital. Este indicador se llama Disponibilidad y forma parte de una metodología industrial clave: la Efectividad Global de los Equipos (Overall Equipment Effectiveness, OEE).

¿Qué es el OEE?
El OEE (Overall Equipment Effectiveness) es una métrica compuesta por tres factores multiplicativos: Disponibilidad × Rendimiento × Calidad. Esta práctica se enfoca exclusivamente en el primer factor: la Disponibilidad (A).

El Concepto Industrial (Sin Código)

Imaginemos un torno o una fresadora en un taller
Tiempo programado (Tprog)
Es la jornada laboral asignada a la máquina. Por ejemplo, un turno completo de 8 horas equivale a 480 minutos.
Tiempo de paradas (Tparadas)
Es el tiempo que la máquina estuvo apagada o detenida por fallas mecánicas, falta de material o cambio de herramientas (en el ejemplo, 40 minutos por ajuste de cuchillas).
Tiempo operativo (Toperativo)
Es el tiempo en el que la máquina realmente produjo piezas. Se calcula como la diferencia entre el tiempo programado y el tiempo de paradas.
Toperativo = Tprog − Tparadas

La disponibilidad (A) responde a la pregunta: ¿Qué porcentaje del tiempo planeado estuvo la máquina realmente encendida y disponible para producir?

A = ( Toperativo / Tprog ) × 100
A = ( (480.0 − 40.0) / 480.0 ) × 100
A = ( 440.0 / 480.0 ) × 100
A = 91.67%

def calcular_disponibilidad(tiempo_programado_min, tiempo_paradas_min):
    # 1. Filtros de seguridad (evitan ingresar datos absurdos)
    if tiempo_programado_min <= 0:
        raise ValueError(
            "El turno de trabajo no puede ser 0 ni un número negativo."
        )

    if tiempo_paradas_min < 0:
        raise ValueError("El tiempo de parada no puede ser negativo.")

    if tiempo_paradas_min > tiempo_programado_min:
        raise ValueError(
            "La máquina no puede estar parada más tiempo del que dura el turno."
        )

    # 2. Operación matemática
    tiempo_operativo = tiempo_programado_min - tiempo_paradas_min
    disponibilidad = (tiempo_operativo / tiempo_programado_min) * 100.0

    # 3. Entrega el resultado redondeado a dos decimales
    return round(disponibilidad, 2)

PYTHONCelda de Código — ejecución con datos reales
# Datos registrados en planta
minutos_turno = 480.0      # Turno de 8 horas
minutos_detenida = 40.0  # Parada por cambio de cuchillas

# Intentamos realizar el cálculo
try:
    resultado = calcular_disponibilidad(minutos_turno, minutos_detenida)
    print("--- REPORTE DE PLANTA ---")
    print(f"Turno planificado: {minutos_turno} minutos")
    print(f"Tiempo perdido por paradas: {minutos_detenida} minutos")
    print(f"Disponibilidad de la máquina: {resultado}%")
except ValueError as error:
    print(f"Alerta: Los datos ingresados son erróneos -> {error}")

¿Por qué incluimos validaciones de seguridad en el código?

Candados lógicos contra errores humanos

Un error común al alimentar sistemas de control en ingeniería es ingresar datos erróneos por distracción humana. Las líneas con raise ValueError son candados lógicos:

Escenario Erróneo ¿Qué pasaría sin validación? ¿Qué hace la validación?
Poner 0 en el turno La computadora colapsa por división entre cero (x / 0). Detiene el proceso y avisa: "El turno debe ser mayor a cero".
Poner paradas de −15 min Daría una disponibilidad irreal mayor al 100%. Detiene el cálculo: "El tiempo no puede ser negativo".
Paradas de 500 min en turno de 480 min Daría un número negativo absurdo. Detiene el cálculo: "Las paradas no pueden superar el turno".
Lección clave de ingeniería de datos
En sistemas SCADA, MES y ERP industriales, una validación omitida puede disparar alertas falsas, paradas fantasma o reportes OEE incorrectos que afectan decisiones gerenciales. El código defensivo no es opcional: es estándar profesional.
